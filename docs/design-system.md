# Datatem Design System

Uniform UI foundation for the combined data + shopping system. It is built on Tailwind CSS 4 tokens, Blade components and the Instrument Sans typeface, and it is used by every migrated page in both the storefront and the member area.

## 1. Brand and tokens

Tokens live in `resources/css/tokens.css` and are exported to Tailwind utilities through `@theme` (for example `bg-brand-navy`, `text-brand-navy`, `border-brand-yellow`, `rounded-card`, `rounded-control`).

| Token | Value | Usage |
|---|---|---|
| `brand-navy` | `#0A2038` | Header, primary text, feature surfaces, sidebar |
| `brand-navy-soft` | `#143A5A` | Secondary hover |
| `brand-yellow` | `#F0C232` | Primary actions, header accent border |
| `brand-yellow-strong` | `#D4A81F` | Primary hover |
| `brand-red` | `#DB4650` | Non-text accents only |
| `brand-red-strong` | `#A92D38` | Text-bearing danger |
| `brand-red-strong-hover` | `#8C232D` | Danger hover |
| `surface` / `surface-muted` | `#FCFBF8` / `#F2F0EB` | Page and secondary panels |
| `ink` / `muted` / `line` | `#14171A` / `#5C6472` / `#E1DFD8` | Body text, secondary text, borders |
| `nav-muted` | `#D3DAE6` | Header navigation links on navy |

- Typography: Instrument Sans (bundled by Vite through `@fontsource-variable/instrument-sans`).
- Radii: controls `0.375rem`, cards `0.75rem`.
- Container: `75rem`, inline padding `1rem` (`.container-page`).
- Breakpoints: 40 / 48 / 64 / 80 / 96 rem.
- Rules: no gradients, no pill controls, no glow effects, no decorative emoji or Unicode.

Legacy bridge tokens (`primary-50` … `primary-900`, `mtn`, `airteltigo`, `telecel`) exist only so pre-migration legacy pages render in the brand palette until their phase restyles them. New work uses `brand-*` tokens.

## 3. Navigation model

- Desktop member area: fixed left sidebar grouped as Overview (Dashboard, Shop, Buy data), Orders (Orders, Wallet), Earnings (Referral, Reseller) and Account (Notifications, Profile, Support).
- Desktop public area: top navigation (Home, Shop, Bundles, Stores, Support).
- Mobile everywhere: bottom navigation with Home, Shop, Bundles and Account; the public cart link appears in the header once the shop module ships.
- Admin area: navy sidebar grouped as Overview (Dashboard, Shop catalog), Data (Bundles, Data orders, Top-ups), Finance (Finance overview, Payments), Growth (Users, Resellers, Affiliates, Announcements), Support, Settings; mobile uses the same off-canvas sidebar plus a bottom bar (Dashboard, Orders, Shop, Settings).
- Mobile: every shell has an off-canvas sidebar opened from the topbar menu button, plus bottom navigation.
- Navigation items are generated by `App\Support\Navigation` so all shells stay in sync.

## 4. Accessibility

- All text/background pairs meet WCAG AA 4.5:1; asserted by `tests/Unit/DesignTokensTest.php`.
- Visible 2px focus outlines on every interactive element.
- Skip link targets `#main-content`; navigation landmarks have accessible names.
- The alert dialog is `role="dialog"` with `aria-modal` and a labelled title.
- Motion respects `prefers-reduced-motion`.

## Service page culture

Every service page follows the same pattern; new pages must reuse these primitives instead of inventing their own:

- **Page heading:** `x-ui.page-heading` — back link to All services, a short title, one-line subtitle, and an actions slot (wallet balance + Top up, or Service orders on the hub).
- **Selectable lists:** use the `.service-tab` component class for networks, products or services. Each tab is `role="tab"` with `aria-selected`; choosing one replaces the working panel instead of stacking separate forms.
- **Working panel:** one form/panel at a time, full width on mobile, with practical helper text only where it prevents a mistake.
- **Copy:** sentence case, one-line subtitles, no uppercase eyebrows, no blog/editorial sections, no FAQ or process essays. Explain an outcome only when it changes what the person does.
- **Single-service pages** (AFA) use the compact form + fee/refund summary pattern; no list tabs are needed.
